# 執筆の指示：超基礎から学ぶ高校英語　第一講　英文法編

あなたは大学入試英語に詳しい塾の英語講師です。英文法の1単元（またはいくつか）を、データファイル（YAML）として書きます。組版は自動なので見た目は考えなくてよい。

## 最初に読むもの
1. `series/design/10_grammar_outline.md`：全単元の構成表。担当単元の節・文法事項・★・例題の型・問題数・典型的な誤り・ページの割り当て、第4章の「単元をまたいでそろえる用語と判断手順（どの単元で定義するか）」、第5章の★と★★の線引き。**ここに書いたとおりに作る。**
2. `series/design/03_writer_brief.md`：書き方・正確さ・著作権・英語例文・YAML の注意（そのまま守る。ただし分量と ID は下の指示で置きかえる）。
3. `series/design/02_data_format.md`：記法（`*…*` の太字下線、`＿` の欠けた位置、`{{…}}` の赤シート、`<<用語>>`、`@s011` などの参照、`__…__①` の下線）。
4. `series/review/v1/FIX_BRIEF.md` の「YAML の注意」（値の頭に @ や * を置かない、on・off・yes・no は引用符で囲む、1行の {…} の中に半角コンマを含む文を書かない）。
5. 見本：`series/src/eg01.yaml`（関係詞の本）の第1節 s01（本文・側注・例文・確認・例題 worked・要点）と、`series/build/eg01/honsatsu.pdf` の 5〜8 ページ。

## 本書の条件
- 読者：塾に通わずに大学入試を目指す高校生。中学英語があやふやな人でも読めるよう、超基礎から説明する。ただし内容は省略しない。
- 難易度：★（共通テスト水準）と★★（GMARCH 標準）だけ。問題の `lv` は 1 か 2。★★★ の内容は書かない（構成表の「入試演習編へ回す」を見る）。
- 1単元は構成表のページ数（16〜20）に収まる量にする。目安：1節あたり本文の段落 3〜5、例文 3〜5、表か手順 1、確認 2〜3、例題 2、問題は構成表の数、要点 3〜4。

## 単元のデータの形

```yaml
chapters:
- id: c02                      # 単元の ID（構成表の単元番号を2桁で）
  title: 時制                  # 構成表どおり
  lead: 単元の導入 2〜3文。この単元で何ができるようになるか。
  intro: 中学の復習。この単元の前提になる中学の文法を 3〜5 文で短く説明する（記法を使ってよい）。
  sections:
  - id: s021                   # 単元2の第1節。g1.yaml の節 ID と同じ（変えない）
    title: …（g1.yaml と同じ）
    aim: この節で何ができるようになるかを1文で（「〜できるようになる。」）。
    body: [...]                # 関係詞の本と同じ形（h・p・ex・steps・table・check、側注 notes）
    examples: [...]            # 例文（id は e0201〜）
    worked: [...]              # 例題2問（q・choices（4択のとき）・steps 3〜4・ans・point）
    summary: [...]             # 要点 3〜4文。答えを {{…}} で囲む
problems:
- id: q02001                   # 単元2の問題は q02001〜
  sec: s021
  set: 節末                    # 節末 / 前提 / 確認テスト
  lv: 1
  kind: 4択                    # 4択・正誤・整序・補充・和訳・英作（読解は使わない）
  min: 1
  inst: …（同じ形が続くときは省略可）
  q: …
  choices: [...]
  ans: "2"
  why: 正解の根拠（1〜3行）
  trap: よくある間違い1つと、なぜ引っかかるか
```

- **前提チェック（set: 前提）**：単元の入口に3問。中学の文法で、この単元に入る前に確かめること（★）。`sec` は単元の第1節。
- **節末問題（set: 節末）**：構成表の数（6〜8）。★ を半分以上。例題と同じ考え方で解ける類題を、場面と語を変えて繰り返す。
- **確認テスト（set: 確認テスト）**：10問。担当単元から8問（節を混ぜる）と、それより前の単元から2問（構成表の単元の順で前のもの。単元1は前の単元がないので10問とも単元1）。前の単元から出す問題の `sec` はその単元の節 ID にする。
- 全問に why と trap。答えが1つに決まるかを、ほかの選択肢・並べ方・直し方を1つずつ当てはめて確かめる。4択の正解の位置は気にしなくてよい（あとで機械でならす）。正誤の誤りの位置は①〜④をばらけさせる。
- **用語**：構成表の第4章で「担当単元で定義する」とされた用語は、初出で `<<用語>>` と書き、側注 `{kind: 用語, term, yomi, text}`（複数行の形で）を付ける。ほかの単元で定義される用語は `<<>>` を付けずに使い、必要なら `（@s015）` のように定義の節を参照する。構成表にない新しい用語を定義するときは、ほかの単元と重ならない名前にする。
- **［ ］〈 〉（ ）の記号**：構成表の第4章の決まりどおりに使う。
- **ID**：例文 `e{uu}01`〜、問題 `q{uu}001`〜（uu は単元番号2桁）。節 ID は g1.yaml の `s{uu}{n}` を使う。

## 出力と検査
- 担当単元を `series/src/parts/g1_c{uu}.yaml` に書く（`chapters:` に担当単元だけ、`problems:` にその単元の全問）。`series/src/g1.yaml` は編集しない（ほかの執筆者と同時に作業するため）。
- 書き終えたら、**ほかの単元のファイルも含めて** `python3 series/tools/validate.py series/src/g1.yaml series/src/parts/g1_*.yaml` を実行し、ERROR 0（用語の二重定義は、ほかの単元と合わせたときにだけ見つかる）。WARN のうち、自分の単元のものは1つずつ見て直す（正解の位置の偏りの WARN は無視してよい）。組版は実行しない。
- 定義済みの用語の一覧：`series/design/12_terms.md`（データから自動で作る。ここにある用語は定義せずに使い、必要なら定義の節を @ で参照する）。

## 報告
各節の要点、例文数・例題数・問題数（区分別・★別・形式別）、定義した用語、自信のない点（答えが2つになるおそれ、語法の細部）を短く報告する。
